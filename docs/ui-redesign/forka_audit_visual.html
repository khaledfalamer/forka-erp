Suggested 4 sprints
  • Sprint 1: colours/fonts (tokens), shared header, menu overflow, focus rings, phone frame.
  • Sprint 2: inventory table prototype and procurement request detail.
  • Sprint 3: hiring request wizard, candidate/request search, dashboard empty states.
  • Sprint 4: board on phones, task form, calendar/timeline, careers editor, polish.
Rules he sets for the developer
  • Every role sees exactly the same data and actions as today.
  • Keep the personal PIN for Operations and keep CEO approval.
  • Don't show candidate, staff, supplier contact or salary data to more people.
  • Don't create or edit live business data while testing.
  • Test at 4 screen sizes, in English and Arabic, at 200% zoom and with the keyboard only.
He says: Keep the warm ivory, dark ink and bronze, and keep serif for page titles only. Use a clear sans-serif for menus, labels, tables and numbers, with body text at 14–16 px and labels at least 13 px. Line up numbers using tabular figures. Use one spacing scale (4/8/12/16/24/32) and 8–12 px corners, and show a visible focus ring. Status badges need text and colour, and "Urgent" must not look like the default tag.

Forka People (HRIS) wasn't reviewed

The demo account he used didn't show Forka People as an app. He only saw the admin "People and access" page and the Boards staff directory. He says not to assume the HR system is missing and not to redesign it from those screens.

What he suggests once access is given:
  • Use the same shared header and a people-first dashboard.
  • Audit staff profiles, attendance, leave, documents, payroll and employee/manager self-service.
  • Don't add or remove HR workflows.
  • Keep salary and ID data locked to the current roles.

Next step: give the auditor a read-only People login, then ask for a second round.
